# UniVPN Connect 设计

日期：2026-10-09。状态：用户已授权按五阶段执行；本文记录实现边界与验收要求。发行名称为 **UniVPN Connect**；原 `univpn-forward` TCP 工具继续兼容。本文不包含机器、账号或网关私有信息。

## 目标与边界

实现基于 OpenConnect 的 UniVPN/Huawei IPv4/TLS 原生客户端，提供 CLI 和桌面应用。可保存多个网关和多个用户名/密码，便捷切换。完成 GitHub 建仓、GitLab 注册、正式 MR 提交之前的代码、文档、构建、测试、脱敏和提交材料；不执行这些外部发布操作，不替用户认证 DCO。

首版支持已观察的密码认证、双 TLS 通道、虚拟 IPv4、协议 framing 与保活。UDP/ICMP/多目标能力以真实探测为准；不预先宣称 DNS/路由下发、其他固件、MFA、SSO、IPv6、外层 DTLS 或 iPhone 原生 VPN 支持。现有私有自动连接服务保持运行，不覆盖其启动项、SSH 配置、密钥或路由。

## 方案选择

1. **OpenConnect C 核心＋Python 管理层＋pywebview 桌面（采用）**：复用内核 TCP 和上游隧道/平台基础设施；CLI/管理层与桌面桥共用业务逻辑。发布冻结安装包，不要求用户安装 Python 或 uv。
2. 完善 Python 手写 TCP 后做 SOCKS5：适合轻量代理，但重复维护 TCP 栈、会话分流，不能替代原生 VPN。保留已有转发入口，不优先扩大该路线。
3. 每个平台独立原生 GUI/协议实现：系统集成更深，四个平台协议与测试成本更高。首版不采用。

## 原生协议结构

新增 `univpn.c`，在上游 `vpn_proto` 注册 `univpn`。使用上游 TLS、证书校验、认证表单、包队列和 TUN；不迁移 Python 中构造 TCP 的逻辑。控制连接与数据连接拥有独立 TLS 状态，信任设置一致；第二通道须验证与已经验证的第一通道相同的对端证书身份。

握手状态：TLS → 340-byte FirstConnect → AUTH → REQVIP → 第二 TLS/DATA_CONNECT → IPv4传输。解析长度/版本/状态/TLV；保留分片读取状态；限制握手总时限，支持取消。用户名/密码通过认证表单取得，密码不入日志；cookie/session数据不进入普通状态输出。

运行状态：控制10秒、数据15秒保活，两个通道被及时读取，写缓冲可处理 partial write，所有包/心跳写入有明确顺序。TLS错误触发资源清理或受控重连；重新登录可能改变VIP，旧TCP不能承诺保活。断开必须释放控制通道、数据通道、缓冲与令牌。通过库销毁路径验证无遗留。

网关未验证的路由/DNS字段不能猜测后自动应用。管理层允许用户配置明确的IPv4网段和可选DNS；默认分流，仅访问用户设置的网段；不擅自接管默认路由。Mac实测使用临时接口、临时目标主机路由，保存并校验撤销结果。

## 配置与凭据模型

`Gateways`：稳定ID、显示名、主机、端口、认证域、证书验证方式/可信CA/完整证书指纹、IPv4网段数组、可选DNS、首选凭据ID。

`Accounts`：稳定ID、显示名、用户名、系统凭据引用。密码只存系统凭据库，不存JSON。账户独立于网关，可以被多个网关选用；同网关可切换账户。删除凭据同时删除对应系统密码项；仍被配置引用时要求用户明确选择替代/取消。

本地原子保存 schema版本、网关、账户元数据、上次选择、主题、自动重连偏好。配置/状态目录权限限制当前用户。导出只含网关和账户元数据，不含密码、会话令牌或个人测试日志。导入验证所有字段，不能通过路径、shell参数、URI注入命令；出现未知schema或缺少凭据时明确提示。

系统库：Mac Keychain、Windows凭据库、Linux Secret Service。没有可用安全凭据库时允许本次输入，不偷偷落盘到明文替代库。根权限的网络进程不直接读取用户系统凭据库；密码由未提权管理层通过受限IPC/标准输入传给它。

## 桌面 UI

参考 Shadowrocket 的信息组织和操作密度，不复制其资产、商标或宣称一致布局。当前其主窗口未能自动读取，待窗口可读取后核对细节。

默认窗口约900×650；侧栏为“连接 / 配置 / 账户 / 日志 / 设置”。主界面顶部显示实际连接状态、选中网关、账户下拉框和连接开关。下方服务器列表带选择标记、网关备注、简短地址、编辑按钮；支持新增、编辑、复制、删除和搜索。配置详情包含认证域、TLS信任、分流网段/DNS。

账户页显示账户备注、用户名及“密码已保存/本次输入”，密码遮挡；新增/编辑弹窗支持记住密码开关。读取账户列表不能返回密码；编辑已有账号不会自动把密码填进网页。连接时选择账户后由管理层从凭据库读取。

状态：未连接、连接中、已连接、重连中、断开中、失败。操作立即显示进度、可取消，后台线程不会卡住界面。失败展示具体阶段和可操作原因；认证/证书错误不会自动反复提示/重试。活动连接切换到其他网关/账户必须明确“断开并切换”；单个活动VPN避免路由冲突。

显示连接时长、分配IP、连接方式和可取得的实际收发统计；没有数据就显示“—”，不伪造数字。日志限长、可筛选/复制脱敏内容。主题为系统/浅色/暗色，持久化。窗口关闭可保留当前连接但告知用户；退出应用时默认断开，不能静默留下未知进程。

桌面通过本地 pywebview bridge调用管理层，不开放特权HTTP API，不允许跳转远端页面。CLI/桌面共用同一配置和控制状态，所有bridge参数再次验证。

## 权限和进程

UI普通用户运行；网络操作由系统临时授权的后台进程完成。首版不安装常驻root服务、不保存管理员密码、不要求付费签名。Mac使用系统管理员授权；Windows使用UAC；Linux使用polkit或明确的管理员启动路径。没有权限时给出清楚的操作入口，不能假装连接成功。

密码不进入进程命令行、普通环境变量、日志和配置；授权启动链使用受限IPC/内存管道传递。连接PID、开始时间、会话ID、二进制来源被记录并校验；断开只针对该会话，不使用全局pkill。需要处理重复点击、其他实例、后台退出、PID复用、关闭窗口和OS结束进程。

## 打包与许可

Mac arm64/x86_64 app/DMG，Windows安装包＋便携版，Linux deb＋便携包；CLI独立入口。各平台冻结时打包相应OpenConnect核心、TLS依赖、路由脚本、许可与对应修改源码/补丁。上游LGPLv2.1与脚本依赖许可单独清楚记录；Python自身MIT不覆盖第三方。无付费签名不等于无系统确认；不得自动关闭系统安全机制。

版本来源一处；GUI、CLI、包名、发布标签一致。发布前保留旧alpha资产，但新能力不能误标为旧TCP版本已验证。构建过程遇到缺少平台核心时明确失败，不生成名为完整VPN的空壳成功包。

## 验证与风险

本地模拟网关测试TLS信任、双通道、协议片段、认证失败、错误长度/TLV、并发、保活、异常关闭和清理。C正常测试＋ASan/UBSan；Python管理层测试凭据/配置/参数/PID/重连；UI交互测试多配置账户、导入导出、错误、重复操作、主题和键盘可用性。

真实Mac只测试新端口/独立状态；Linux可在隔离环境/GPU用户自有测试区验证，不影响训练；Windows/Intel只能在获得环境时真机验收。CI定义、交叉编译和真机结果分别记录。无法获得授权或硬件时保留该项未验证，并继续其余工作。
